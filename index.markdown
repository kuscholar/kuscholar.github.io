        <div class="work-aside">

          <div class="work-tags" aria-label="Technologies and disciplines">
            <span>Repository pattern</span><span>Caching</span><span>State</span>
          </div>
        </div>
        <div class="work-body">
          <h3>Making the right behavior the easy behavior.</h3>
          <p>
            Refactored view-model ownership and introduced a repository layer to give product
            code a clearer data boundary. The result was simpler state management, stronger cache
            behavior, and fewer unnecessary network requests.
          </p>
          <ul class="work-points">
            <li><span>Consistency</span> Centralized data access and caching decisions behind a reusable interface.</li>
            <li><span>Efficiency</span> Reduced redundant network activity and its associated cloud cost.</li>
            <li><span>Maintainability</span> Made feature code easier to reason about, test, and evolve.</li>
          </ul>
        </div>
      </article>

      <article class="work-item">
        <div class="work-aside">

          </div>
        </div>
        <div class="work-body">
          <h3>Improving confidence from development to release.</h3>
          <p>
            Strengthened the feedback loops around a production iOS app by expanding automated
            coverage, adding a Firebase DebugView workflow, and resolving recurring build-machine
            issues.
          </p>
          <ul class="work-points">
            <li><span>Observability</span> Made analytics validation easier before code reached production.</li>
